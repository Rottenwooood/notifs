# S6

> 已废弃：本阶段的 OpenCode 回复桥通过解析模型最终文本发消息，违反 v0.2.0 的 agent 出站契约。新契约要求 agent 自己调用 MCP `send` 或 HTTP POST；本文仅保留历史记录。

## 1 开头

notifs 0.2 是面向人、程序和 agent 的订阅式通信中心；当前阶段 S6 完成了 OpenCode 回复桥与同一个飞书 bot 的真实 agent 闭环。下一阶段入口：在具体 agent 的 prompt/工具权限中禁止用本地 form/question 代替 notifs，再决定本地或云端部署并切换生产。

## 3 本阶段约束

- C1：只补 OpenCode 宿主回复桥和真实闭环，不改消息、订阅、权限与既有 adapter 语义。
- C2：产出回复桥、测试、构建入口、配置文档和验证记录。
- C3：真实飞书消息经同一个 bot 到 OpenCode，再把模型回复送回同一会话。
- C4：测试窗口内可停 relay 的 `feishu-events`，并发送本次所需真实飞书消息。
- C5：不改全局 OpenCode 配置、不回显凭据、不删旧数据、不 push。
- C6：预算 4 小时，真实模型调用最多 3 次；失败立即恢复旧 producer。
