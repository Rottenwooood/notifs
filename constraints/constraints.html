约束清单

项目：notifs v0.2.0 文档时效性收口　阶段：docs-v0.2.0-alignment

约束

编号约束
C1范围是让文档陈述与 0.2.0 代码及已完成状态一致：MCP 配置形状、保留清理能力、发布完成状态、生产拓扑、部署模板、构建提示文本。不做功能新增、不改投递与路由语义、不改测试断言、不删历史验收证据、不删本地发布包、不 push。
C2产物为 README、docs/mcp.md、docs/release-plan.md、docs/boundaries.md、docs/configuration.md、docs/validation/stage-8.md 的修正，deploy 说明与 unit 模板的更新，CHANGELOG 的未发布段，tools/build.mjs 提示行，以及本阶段约束清单和其生成稿。
C3验收标准是文档陈述与代码逐条可核对：按修正后的 MCP 配置能被 OpenCode 2.x 识别并连通、按 README 所述保留清理真实执行、发布路线不再把已完成项写成未完成；同时 pnpm typecheck、pnpm test、pnpm build 通过，约束清单渲染校验退出 0。
C4允许 pnpm、node、curl、opencode run、opencode mcp list、git 本地提交、timeout，以及 ~/.config/opencode/scripts 下的脚本；测试使用隔离的数据目录、配置目录和端口。
C5不 push、不 reset --hard、不改写历史、不使用 pkill -f 或 killall、不回显凭据、不修改全局 OpenCode 配置、不操作生产 relay、不删除 docs/validation 下的历史结果文件。
C6预算 60 分钟；真实模型调用最多 2 次；文档改动控制在 12 个文件以内；不新增长期运行的进程。
