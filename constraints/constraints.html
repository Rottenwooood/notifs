约束清单

项目：notifs 投递健壮性修复　阶段：delivery-robustness

约束

编号约束
C1范围是修复源码审计确认的投递与入口缺陷：调度器忽略 retryable、飞书私聊被相关性过滤丢弃、CLI 无值开关吃掉位置参数、通知适配器不响应停止信号、飞书群机器人文本无截断、feishu-app 的 token 缓存键缺 domain 且失效不清理。不做 last_error 落库、held 查询接口和凭据解析白名单，这些改动涉及 schema 与安全策略，另行决策。
C2产物为 contracts 的两个内部投递操作、store 的 fail/release、内核分支、调度循环重写、5 个适配器的信号与截断、CLI 参数解析、对应测试、文档与 CHANGELOG 更新，以及本阶段约束清单和收尾记录。
C3验收标准是真实入口可观察：不可重试错误第一次失败后批次即 held 且只调用一次适配器；可重试错误在退避后重试并最终 received；私聊事件经入站 bridge 发布；CLI 的 --print/--force 不再吞掉位置参数；typecheck、测试与构建通过。
C4允许 pnpm、node、curl、timeout、git 本地提交、opencode mcp list；测试使用隔离数据目录、配置目录与端口。
C5不 push、不 reset --hard、不改写历史、不使用 pkill -f 或 killall 终止进程、不回显凭据、不修改生产 relay、不改全局 OpenCode 配置。
C6预算 120 分钟；不新增依赖；产物不影响既有 HTTP 路由表与管理工具集。

范围

做

  • 调度器消费 retryable 并按退避重试
  • 飞书私聊相关性过滤、CLI 布尔开关
  • 适配器停止信号、飞书截断、token 缓存键与失效
  • 回归测试与文档同步

不做

  • last_error 落库与 held 查询接口
  • 环境变量解析白名单与 domain 限制
  • 新增管理命令或 MCP 工具
